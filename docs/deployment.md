# Deployment

Seatline ships as two deployables:

| Part | What it is | Recommended host |
|---|---|---|
| `api/` | ASP.NET Core container (`api/Dockerfile`), listens on port 8080 | **Render** (free web service, Docker) |
| Database | PostgreSQL 17 | **Neon** (free tier, does not expire) |
| `web/` | Static Vite build (`npm run build` → `dist/`) | **Vercel** (free, `web/vercel.json` handles SPA routes) |

> Free tiers and their limits change often. Check each provider's current pricing page before you sign up.
> Render's free web services sleep after ~15 minutes idle, so the first request can take ~30–60 s.
> That's fine for a portfolio demo. Mention it in the README.

## Configuration reference

The API reads standard ASP.NET Core configuration, so every setting can come from an environment variable
(`:` becomes `__`).

| Variable | Required | Example / notes |
|---|---|---|
| `ConnectionStrings__Default` | yes | Npgsql format **or** a URL: `postgresql://user:pass@host/db?sslmode=require` |
| `Jwt__SigningKey` | yes | ≥ 32 random chars: `openssl rand -base64 48` |
| `Cors__AllowedOrigins__0` | yes | The web URL, e.g. `https://seatline.vercel.app` (no trailing slash) |
| `Seed__DemoUsers` | no | `true` to create the three demo accounts |
| `Seed__DemoPassword` | if seeding | Password shown in the README for reviewers |
| `Swagger__Enabled` | no | Defaults to `true` (Swagger is part of the demo) |
| `Database__MigrateOnStartup` | no | Defaults to `true`: migrations run when the container starts |

The web needs one build-time variable: `VITE_API_URL` (the public API URL).

## Option A (recommended): Render + Neon + Vercel

1. **Neon**: create a project (region: Frankfurt) and copy the *pooled* connection string
   (`postgresql://...?sslmode=require`).
2. **Render**: *New → Blueprint*, select the GitHub repo. Render reads `render.yaml` and asks for the
   `sync: false` values:
   - `ConnectionStrings__Default` = the Neon URL
   - `Seed__DemoPassword` = the demo password
   - `Cors__AllowedOrigins__0` = the Vercel URL (you can fill it after step 3 and redeploy)

   `Jwt__SigningKey` is generated by Render. When the deploy is green, open `https://<service>.onrender.com/health`
   and `/swagger`.
3. **Vercel**: *Add New → Project*, import the repo, set **Root Directory = `web`** (framework preset: Vite) and add
   `VITE_API_URL=https://<service>.onrender.com`. Deploy.
4. Back in Render, set `Cors__AllowedOrigins__0` to the Vercel URL if you haven't, and redeploy.
5. Smoke test: open the Vercel URL → *Try the demo* → sign in as `admin@seatline.dev` → *Box office*.

## Option B: Railway (API + Postgres in one place)

Railway runs the Dockerfile and provides Postgres in the same project (paid usage after the trial credit).

1. *New Project → Deploy from GitHub repo*, set the service **Root Directory** to `api`.
2. *New → Database → PostgreSQL*. In the API service variables, set
   `ConnectionStrings__Default=${{Postgres.DATABASE_URL}}` (the API understands URLs), plus `Jwt__SigningKey`,
   `Cors__AllowedOrigins__0`, `Seed__DemoUsers`, `Seed__DemoPassword`, and `PORT=8080`.
3. *Settings → Networking → Generate domain*. Web on Vercel as in option A.

## Option C: Fly.io

Fly.io runs the same image close to Madrid (`mad` region) but requires a payment method.

```bash
cd api
fly launch --no-deploy --name seatline-api --region mad --internal-port 8080
fly secrets set ConnectionStrings__Default="postgresql://..." Jwt__SigningKey="$(openssl rand -base64 48)" \
  Cors__AllowedOrigins__0="https://seatline.vercel.app" Seed__DemoUsers=true Seed__DemoPassword="..."
fly deploy
```

Use Neon for the database (Fly's managed Postgres is paid).

## Checklist before going public

- [ ] `Jwt__SigningKey` is unique to production (never the dev key from `appsettings.Development.json`)
- [ ] CORS lists only the real web origin
- [ ] `/health` returns `Healthy`
- [ ] Demo accounts work and are listed in the README
- [ ] README badge and demo links point at the live URLs
